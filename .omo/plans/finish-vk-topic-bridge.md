# finish-vk-topic-bridge — Work Plan

## TL;DR (For humans)

**What you'll get:** Функционально законченный продукт по Product Spec: полноценный Telegram Admin UI (ReplyKeyboard-клавиатура, мастер регистрации чата, выбор topic-назначений включая General, тумблеры, диагностика доставки, смена чата), VK-интерфейс для пользователей (помощь, алиасы, ручная пересылка одного сообщения), автоматическая пересылка стены и вложений (фото/видео/документы ≤50 МБ, частичный успех, предупреждения), надёжность (General fallback с уведомлением владельцев, персистентный VK-cursor, fail-closed диагностика неоднозначных доставок), полный набор acceptance-тестов по всем US/AC и production-развёртывание (PM2, backup/restore, runbook).

**Why this approach:** Один план закрывает оставшиеся стадии 7–12 целиком, потому что они связаны общей шиной: General-модель миграции нужна и UI, и fallback, и алиасам; multi-call публикация нужна и стене, и ручной пересылке; readiness-модель меняется для всех трёх потоков сразу. Слоёная архитектура сохраняется: UI-слои только оркестрируют существующие use cases, fail-closed семантика доставки расширяется, а не переписывается.

**What it will NOT do:** Никаких FastAPI/Redis/Celery/Kafka/DI-фреймворков/микросервисов. Никакой синхронизации редактирования/удаления VK↔Telegram. Никакого `VK_SOURCE_PEER_ID`, inline-клавиатур, Scenes Wizard, `can_manage_topics`, ручного 👍 и молчаливого fallback в General для явно выбранного пользователем topic.

**Effort:** XL (стадии 7–12)
**Risk:** High — ключевые риски: (1) VK video без прямого download-URL (лечится предупреждением по docs/03 §12.5), (2) hosted Bot API лимит 10 МБ на фото (частичный успех уже продуктовая семантика), (3) миграция three-state General (`configured` флаг + nullable topic id) должна согласованно пройти через ORM/DTO/репозитории/UI.
**Decisions to sanity-check:** явный General хранится парой `telegram_*_topic_configured=True` + `topic_id=NULL` (драфт :32/:169/:185 прямо требует configured-флаги и запрещает sentinel-ID; NULL остаётся «не настроено» только при configured=False); VK-курсор хранится как JSON-файл VKBottle в `runtime/vk_cursor/` (не SQLite — атомарности между VK и Telegram всё равно не бывает); временные `/topics`/`/set_topic` удаляются при появлении Admin UI.

Your next move: Подтвердить план; исполнение волнами Sisyphus (sisyphus-junior), human gates — только владельцем вручную.
