# US-01. Доступ owner к Telegram-боту

**Как owner, я хочу иметь доступ к административному Telegram-боту только по своему Telegram User ID, чтобы посторонние не могли управлять интеграцией.**

## Acceptance Criteria

### AC-01.1
**Given** Telegram User ID пользователя есть в `OWNER_IDS`  
**When** пользователь пишет Telegram-боту  
**Then** бот обрабатывает его запросы и показывает административный интерфейс.

### AC-01.2
**Given** Telegram User ID пользователя отсутствует в `OWNER_IDS`  
**When** пользователь пишет Telegram-боту  
**Then** бот никак не отвечает пользователю.

---

# US-02. Регистрация Telegram-чата

**Как owner, я хочу зарегистрировать Telegram-чат, чтобы система знала, куда публиковать сообщения.**

## Acceptance Criteria

### AC-02.1
**Given** Telegram-чат ещё не зарегистрирован  
**When** owner запускает `/start`  
**Then** бот сообщает, что необходимо добавить его в нужный Telegram-чат и выполнить команду регистрации внутри этого чата.

### AC-02.2
**Given** owner выполнил команду регистрации в допустимом Telegram-чате  
**When** бот успешно идентифицировал чат  
**Then** чат сохраняется в SQLite.

### AC-02.3
**Given** чат зарегистрирован и необходимые права подтверждены  
**When** регистрация завершена  
**Then** owner получает постоянную административную клавиатуру.

---

# US-03. Проверка прав Telegram-бота

**Как owner, я хочу сразу узнать, каких прав не хватает Telegram-боту, чтобы не обнаружить проблему только при первой пересылке.**

## Acceptance Criteria

### AC-03.1
**Given** owner регистрирует Telegram-чат  
**When** у бота отсутствует одно или несколько обязательных прав  
**Then** бот явно перечисляет отсутствующие права и требует выдать их.

### AC-03.2
**Given** обязательных прав недостаточно  
**When** проверка прав завершена  
**Then** мастер не считает настройку чата полностью успешной.

### AC-03.3
Бот должен проверить возможность как минимум:

- отправлять текстовые сообщения;
- отправлять фото;
- отправлять видео;
- отправлять документы;
- публиковать в используемых топиках.

---

# US-04. Получение списка топиков

**Как owner, я хочу видеть актуальные топики Telegram-чата, чтобы выбирать назначения без ручного ввода ID.**

## Acceptance Criteria

### AC-04.1
**Given** пользовательская Telegram MTProto-сессия авторизована и имеет доступ к зарегистрированному чату  
**When** owner запрашивает обновление топиков  
**Then** система получает актуальный список топиков через пользовательский MTProto-клиент.

### AC-04.2
**Given** список топиков обновлён  
**When** owner открывает настройки топиков  
**Then** отображаются актуальные названия топиков и их текущие назначения.

---

# US-05. Настройка автопересылки VK-чата

**Как owner, я хочу выбрать один Telegram-топик для всех автоматически отобранных сообщений VK-чата.**

## Acceptance Criteria

### AC-05.1
**Given** список топиков доступен  
**When** owner выбирает номер топика назначения для VK-чата  
**Then** выбранный топик сохраняется в SQLite.

### AC-05.2
`@all` и хештеги используют один и тот же настроенный топик назначения.

---

# US-06. Автопересылка по хештегу

**Как пользователь Telegram-чата, я хочу получать сообщения VK с хештегами автоматически.**

## Acceptance Criteria

### AC-06.1
**Given** автопересылка по хештегам включена  
**And** VK-сообщение содержит любой хештег  
**When** сообщение обработано  
**Then** создаётся одна Telegram-публикация в настроенном топике.

### AC-06.2
Оригинальный текст переносится без изменений.

### AC-06.3
К публикации добавляется `#извк`.

### AC-06.4
К публикации добавляется гиперсылка имя и фамилия автора, ведущая на его профиль вк.

---

# US-07. Автопересылка по @all

**Как пользователь Telegram-чата, я хочу отдельно видеть важные сообщения VK с `@all`.**

## Acceptance Criteria

### AC-07.1
**Given** автопересылка по `@all` включена  
**And** VK-сообщение содержит `@all`  
**When** сообщение обработано  
**Then** создаётся одна Telegram-публикация в общем настроенном топике сообщений VK-чата.

### AC-07.2
К публикации добавляются:

- `#извк`;
- `#извкважно`.

### AC-07.3
**Given** сообщение одновременно содержит `@all` и любой хештег  
**When** оба фильтра совпали  
**Then** создаётся только одна Telegram-публикация.

---

# US-08. Полная обработка is_cropped

**Как пользователь, я хочу получать полное сообщение, даже если событие VK пришло урезанным.**

## Acceptance Criteria

### AC-08.1
**Given** входящее VK-событие содержит `is_cropped = true`  
**When** сервис начинает обработку  
**Then** он дополнительно получает полную версию исходного сообщения через VK API.

### AC-08.2
По полной версии выполняются:

- анализ `@all`;
- анализ хештегов;
- чтение текста;
- чтение вложений;
- формирование Telegram-публикации.

---

# US-09. Перенос автора сообщения

**Как читатель Telegram, я хочу видеть автора исходного сообщения VK.**

## Acceptance Criteria

### AC-09.1
В Telegram-публикации отображаются имя и фамилия автора VK.

### AC-09.2
Имя и фамилия являются гиперссылкой на профиль этого пользователя VK.

---

# US-10. Перенос вложений

**Как читатель Telegram, я хочу получать поддерживаемые вложения вместе с сообщением.**

## Acceptance Criteria

### AC-10.1
Поддерживаются:

- фото;
- видео;
- документы до 50 МБ.

### AC-10.2
Ошибка одного вложения не отменяет отправку текста и остальных успешно обработанных вложений.

### AC-10.3
Если конкретное вложение невозможно перенести, в Telegram-публикации добавляется отдельная понятная строка об этом вложении.

---

# US-11. Обработка слишком большого файла

**Как пользователь, я хочу понимать, почему большой файл не был перенесён.**

## Acceptance Criteria

### AC-11.1
**Given** размер документа превышает 50 МБ  
**When** сервис обрабатывает вложение  
**Then** документ не загружается в Telegram.

### AC-11.2
В Telegram-публикации явно указывается:

- название файла, если оно доступно;
- что размер превышает 50 МБ;
- что файл нужно открыть в VK.

---

# US-12. Обработка неподдерживаемых вложений

**Как пользователь, я хочу явно видеть, какое вложение система не поддержала.**

## Acceptance Criteria

### AC-12.1
Не поддерживаются как минимум:

- голосовые сообщения;
- аудиозаписи;
- видеосообщения / кругляшки.

### AC-12.2
Для каждого пропущенного вложения создаётся отдельное понятное предупреждение.

### AC-12.3
Несколько неподдерживаемых вложений не схлопываются в одну общую фразу.

---

# US-13. Реакция 👍 в VK

**Как пользователь VK, я хочу видеть, что сообщение успешно обработано мостом.**

## Acceptance Criteria

### AC-13.1
**Given** Telegram-публикация успешно создана  
**When** обработка завершена  
**Then** VK-бот ставит исходному сообщению реакцию 👍.

### AC-13.2
**Given** часть вложений была пропущена, но публикация создана  
**Then** реакция 👍 всё равно ставится.

### AC-13.3
**Given** Telegram-публикация вообще не была создана  
**Then** реакция 👍 не ставится.

---

# US-14. Пересылка поста стены VK

**Как пользователь Telegram, я хочу автоматически видеть новые посты стены сообщества.**

## Acceptance Criteria

### AC-14.1
**Given** автопересылка стены включена  
**When** появляется новый пост стены  
**Then** он публикуется в отдельном настроенном Telegram-топике.

### AC-14.2
Передаются только поддерживаемые:

- текст;
- фото;
- видео;
- документы.

### AC-14.3
Добавляется `#изстенывк`.

### AC-14.4
В публикации обязательно присутствует ссылка на оригинальный VK-пост.

---

# US-15. Ручная пересылка одного сообщения

**Как пользователь VK-бота, я хочу вручную переслать одно сообщение в нужный Telegram-топик.**

## Acceptance Criteria

### AC-15.1
**Given** пользователь передал ровно одно пересланное сообщение  
**When** бот принимает его  
**Then** бот показывает список доступных Telegram-топиков с номерами.

### AC-15.2
Пользователь может:

- отправить номер топика;
- нажать `Отмена`.

### AC-15.3
Reply-контекст исходного сообщения не переносится.

### AC-15.4
Вложенные `fwd_messages` не разворачиваются как отдельная цепочка сообщений.

---

# US-16. Ошибка при нескольких сообщениях

**Как пользователь VK-бота, я хочу получить понятную ошибку, если передал больше одного сообщения.**

## Acceptance Criteria

### AC-16.1
**Given** пользователь передал два или более сообщений одной ручной операцией  
**When** VK-бот получает их  
**Then** бот сообщает, что поддерживается только одно сообщение за операцию.

### AC-16.2
FSM выбора топика не запускается.

### AC-16.3
Ни одно из сообщений не публикуется в Telegram.

---

# US-17. Алиасы топиков

**Как пользователь VK-бота, я хочу назначать короткие алиасы топикам, чтобы не искать номер каждый раз.**

## Acceptance Criteria

Алиас:

- уникален в пределах пользователя;
- сравнивается без учёта регистра;
- не содержит пробелов;
- не совпадает с системными командами / кнопками.

Пользователь может:

- добавить алиас;
- изменить алиас;
- удалить алиас;
- увидеть текущие алиасы рядом со списком топиков.

---

# US-18. Неизвестный алиас

**Как пользователь VK-бота, я хочу не потеряться, если ввёл неправильный алиас.**

## Acceptance Criteria

### AC-18.1
**Given** алиас не найден  
**When** пользователь пытается выбрать направление  
**Then** бот сообщает, что алиас неизвестен.

### AC-18.2
Бот:

- предлагает настроить алиасы;
- выводит список топиков;
- переводит пользователя в интерактивный выбор номера.

---

# US-19. Help VK-бота

**Как пользователь VK, я хочу получить справку без знания специальных команд.**

## Acceptance Criteria

Одинаковую справку открывают:

- `Начать`;
- `Помощь`;
- `Помоги`;
- `Help`;
- соответствующая кнопка клавиатуры.
Команды регистронезависимые.

Это обычные текстовые триггеры VK-бота, а не Telegram slash-команды.

---

# US-20. Toggle-настройки owners

**Как owner, я хочу видеть действие toggle-кнопки прямо в её названии.**

## Acceptance Criteria

### AC-20.1
Если функция включена, кнопка предлагает её отключить.

### AC-20.2
Если функция выключена, кнопка предлагает её включить.

### AC-20.3
`/start` всегда отправляет клавиатуру, соответствующую текущему состоянию настроек.

### AC-20.4
После изменения toggle-настройки всем owners отправляются:

- уведомление об изменении;
- актуальная обновлённая клавиатура.

---

# US-21. Смена Telegram-чата

**Как owner, я хочу заменить Telegram-чат и начать настройку заново.**

## Acceptance Criteria

### AC-21.1
Перед отвязкой чат требует подтверждение.

### AC-21.2
После подтверждения настройки сбрасываются до заводского состояния.

### AC-21.3
После сброса:

- все три вида автопересылки включены;
- зарегистрированного Telegram-чата нет;
- топики назначения не выбраны;
- старые привязки топиков удалены.

---

# US-22. Fallback при недоступном топике

**Как owner, я хочу, чтобы сообщение не потерялось при удалении настроенного топика.**

## Acceptance Criteria

### AC-22.1
**Given** настроенный топик недоступен  
**When** система пытается создать публикацию  
**Then** публикация отправляется в General / общий топик Telegram-чата.

### AC-22.2
Все owners получают уведомление:

- какой топик оказался недоступен;
- что был использован General fallback.

### AC-22.3
Если fallback-публикация успешна, исходному VK-сообщению ставится 👍.

---

# US-23. MTProto Proxy / SOCKS5 / direct

**Как оператор системы, я хочу управлять способом подключения пользовательского MTProto-клиента к Telegram.**

## Acceptance Criteria

Приоритет Telethon:

1. если заданы все параметры MTProto Proxy — используется MTProto Proxy;
2. иначе, если задан SOCKS5 — используется SOCKS5;
3. иначе — прямое подключение.

Если задана только часть параметров MTProto Proxy, приложение завершается с критической ошибкой конфигурации.

---

# US-24. Local Bot API и SOCKS5

**Как оператор системы, я хочу использовать локальный Telegram Bot API без проксирования локального HTTP-трафика.**

## Acceptance Criteria

### AC-24.1
**Given** `TELEGRAM_BOT_API_URL` указывает на `localhost`, `127.0.0.1` или `::1`  
**When** Telegram-бот выполняет Bot API запрос  
**Then** SOCKS5 для этого HTTP-запроса не применяется.

### AC-24.2
Настройки проксирования Telethon от `TELEGRAM_BOT_API_URL` не зависят.

### AC-24.3
Если Bot API endpoint не локальный, SOCKS5 может использоваться согласно конфигурации приложения.

---

# US-25. Отсутствие синхронизации редактирования

**Как владелец проекта, я хочу ограничить мост однократной доставкой события, чтобы не усложнять систему постоянной синхронизацией.**

## Acceptance Criteria

После успешной публикации система не отслеживает:

- редактирование VK-сообщения;
- удаление VK-сообщения;
- редактирование поста стены;
- удаление поста стены.

Уже созданная Telegram-публикация не изменяется автоматически.

# US-26. Скрипт для авторизации в телеграм аккаунт 

**Как владелец/оператор/owner я хочу скрипт в корне проекта, который авторизирует меня в телеграм аккаунт, чтобы система после запуска использовала авторизированный аккаунт для получения топиков.**

## Acceptance Criteria 

- Скрипт создан в корневой папке проекта 
- Скрипт спрашивает мой номер телефона
- Если установлен пароль аккаунта — должен позволить его вписать для авторизации 
- Если придет смс на аккаунт — должен позволить вписать его для авторизации
- При повторном запуске скрипта при уже авторизованном аккаунте при успешной повторной авторизации в другой аккаунт данные перезаписываются новым аккаунтом, старая авторизация аккаунта забывается.
- Данные авторизации хранятся в специальной папке, папка добавлена в гит игнор.
