# 1. Стек

Обязательный стек:

- Python 3.14;
- SQLite;
- SQLAlchemy ORM;
- Telegram Bot API;
- пользовательский Telegram MTProto-клиент через Telethon;
- VK API.

Конкретный фреймворк Telegram-бота и конкретная библиотека VK-бота в требованиях не фиксируются.

---

# 2. Хранение данных

Рабочая конфигурация хранится в отдельном SQLite-файле.

Через SQLAlchemy должны храниться как минимум:

- зарегистрированный Telegram-чат;
- настройки трёх видов автопересылки;
- выбранный топик для сообщений VK-чата;
- выбранный топик для постов стены;
- известные Telegram-топики и их идентификаторы;
- пользовательские алиасы VK-бота;
- другие рабочие настройки, появившиеся в реализации.

`.env` не используется как хранилище изменяемой бизнес-конфигурации.

---

# 3. Переменные окружения

Минимально необходимы технические секреты и параметры инфраструктуры.

Концептуальный набор:

```env
TELEGRAM_BOT_TOKEN=...
OWNER_IDS=123456789,987654321

TELEGRAM_BOT_API_URL=http://127.0.0.1:8081

TELEGRAM_API_ID=...
TELEGRAM_API_HASH=...

TELEGRAM_MTPROXY_SERVER=127.0.0.1
TELEGRAM_MTPROXY_PORT=1443
TELEGRAM_MTPROXY_SECRET=...

SOCKS5_PROXY_URL=socks5://127.0.0.1:10809

VK_GROUP_TOKEN=...
```

Точное именование переменных может быть изменено при реализации, но смысл должен сохраниться.

## 3.1. OWNER_IDS

Содержит Telegram User ID всех owners.

Telegram-бот полностью игнорирует пользователей, которых нет в списке.

## 3.2. TELEGRAM_BOT_API_URL

Позволяет использовать:

- официальный Telegram Bot API;
- собственный Telegram Bot API endpoint;
- локальный Telegram Bot API.

Если endpoint loopback/local:

- `localhost`;
- `127.0.0.1`;
- `::1`;

SOCKS5 для HTTP-запросов к Bot API автоматически не применяется.

## 3.3. TELEGRAM_MTPROXY_*

Параметры MTProto Proxy:

- server;
- port;
- secret.

Они рассматриваются как единый блок конфигурации.

Если задана только часть параметров, это критическая ошибка.

## 3.4. SOCKS5_PROXY_URL

Опциональный fallback proxy.

Может использоваться:

- Telethon, если MTProto Proxy не настроен;
- Bot API HTTP-клиент, если Bot API endpoint не является локальным.

---

# 4. Telegram Bot API

## 4.1. Назначение

Bot API используется для:

- административного Telegram-бота;
- публикации текста;
- публикации фото;
- публикации видео;
- публикации документов;
- отправки в выбранные топики;
- уведомлений owners;
- работы клавиатуры.

## 4.2. Local Bot API

Проект должен поддерживать пользовательский `TELEGRAM_BOT_API_URL`.

Если endpoint указывает на локальный Bot API:

- приложение обращается к нему напрямую;
- SOCKS5 для локального HTTP-трафика не используется.

Несмотря на возможность Local Bot API работать с большими файлами, продуктовый лимит приложения остаётся 50 МБ.

---

# 5. Telegram MTProto / Telethon

## 5.1. Назначение

Пользовательский Telegram-аккаунт используется только для административного чтения структуры Telegram-чата.

Через Telethon система получает актуальный список топиков.

Пользовательский аккаунт не используется как отправитель контента VK → Telegram.

## 5.2. Авторизация

Должен существовать отдельный Python-скрипт первичной авторизации Telegram-пользователя.

Скрипт:

1. читает `TELEGRAM_API_ID`;
2. читает `TELEGRAM_API_HASH`;
3. авторизует пользователя;
4. создаёт persistent Telethon session;
5. завершает работу.

Основное приложение использует уже существующую session.

## 5.3. Session

Session является секретом уровня авторизованного Telegram-аккаунта и должна храниться вне публичного репозитория.

Путь или способ хранения session определяется реализацией.

---

# 6. Приоритет прокси

## 6.1. Telethon

Строгий приоритет:

1. MTProto Proxy;
2. SOCKS5;
3. direct connection.

### MTProto Proxy

Если заданы:

- `TELEGRAM_MTPROXY_SERVER`;
- `TELEGRAM_MTPROXY_PORT`;
- `TELEGRAM_MTPROXY_SECRET`;

используется MTProto Proxy.

Если указан неполный набор параметров — startup завершается критической ошибкой.

### SOCKS5

Используется только если полный MTProto Proxy не настроен.

### Direct

Используется, если не настроен ни MTProto Proxy, ни SOCKS5.

## 6.2. Bot API

Проксирование Bot API и Telethon — независимые подсистемы.

Если `TELEGRAM_BOT_API_URL` loopback/local, SOCKS5 для Bot API отключается автоматически.

Это не влияет на Telethon.

---

# 7. Startup checks

До перехода приложения в рабочее состояние должны пройти обязательные проверки.

## 7.1. Environment

Проверяются обязательные переменные окружения.

Ошибка обязательной переменной → critical startup error.

## 7.2. MTProto

Проверяются:

- наличие `TELEGRAM_API_ID`;
- наличие `TELEGRAM_API_HASH`;
- наличие пользовательской session;
- валидность / авторизованность session;
- возможность подключиться к Telegram через выбранный transport/proxy.

Если Telegram-чат уже зарегистрирован, дополнительно проверяется:

- доступ пользовательского аккаунта к чату;
- возможность получить список топиков.

Любая критическая проблема MTProto должна останавливать запуск приложения.

## 7.3. Bot API

Проверяется доступность настроенного Bot API endpoint.

## 7.4. SQLite

Проверяется возможность открыть БД и выполнить необходимые миграции / инициализацию схемы.

# 8. Telegram-чат и топики

## 8.1. Регистрация чата

Первичная настройка начинается через `/start` в личном диалоге owner с Telegram-ботом.

Бот ожидает регистрацию Telegram-чата через специальную команду внутри самого чата.

Точное имя команды определяется при реализации.

## 8.2. Проверка прав

Во время регистрации бот обязан проверить права, необходимые как минимум для:

- отправки текста;
- отправки фото;
- отправки видео;
- отправки документов;
- публикации в топиках.

Если права отсутствуют:

- owner получает явный список недостающих прав;
- бот требует выдать их;
- настройка не считается успешно завершённой.

## 8.3. Список топиков

Список топиков получает Telethon через пользовательский MTProto-аккаунт.

Owner может вручную инициировать обновление списка.

В БД хранится локальное представление:

- topic id;
- название;
- текущее назначение.

---

# 9. VK API

Система работает от имени сообщества VK там, где VK API это допускает.

Должны поддерживаться события:

- новые сообщения чата сообщества;
- новые посты стены сообщества.

Сообщество должно быть корректно настроено для работы бота в беседе.

Если необходимых настроек сообщества / разрешений VK недостаточно, система должна выдавать диагностируемую ошибку конфигурации.

---

# 10. Обработка сообщений VK

## 10.1. Полное сообщение

Если событие содержит `is_cropped = true`, необходимо дополнительно получить полную версию сообщения перед анализом.

Фильтрация никогда не должна выполняться только по урезанному объекту.

## 10.2. Фильтры

Есть два независимых toggle:

- `@all`;
- любой хештег.

Оба фильтра ведут в один общий Telegram-топик сообщений VK-чата.

Одновременное совпадение фильтров не создаёт две публикации.

## 10.3. Автор

Система получает данные автора VK и строит кликабельную ссылку на его профиль.

## 10.4. Reply / forwards

Reply-контекст не переносится.

`fwd_messages` не разворачиваются в отдельную цепочку.

Обрабатывается только основное выбранное сообщение.

## 10.5. Реакция

После успешного создания Telegram-публикации вызывается VK API для установки реакции 👍 оригинальному сообщению.

Если публикация не создана — реакция не ставится.

---

# 11. Обработка стены VK

При включённой автопересылке стены система обрабатывает новые посты.

Передаются только:

- текст;
- фото;
- видео;
- документы.

Добавляются:

- `#изстенывк`;
- обязательная ссылка на оригинальный пост.

Остальные типы вложений не преобразуются и отражаются текстовыми предупреждениями в публикации.

---

# 12. Вложения

## 12.1. Лимит

Собственный лимит приложения для документа / файла:

**50 МБ.**

Файл больше 50 МБ:

- не скачивается или не загружается дальше, если размер известен заранее;
- не отправляется в Telegram;
- отражается отдельным предупреждением.

## 12.2. Поддерживаемые типы

- photo;
- video;
- document.

## 12.3. Неподдерживаемые типы

Как минимум:

- audio;
- audio_message / voice;
- video_message / кругляшок;
- прочие типы, не входящие в whitelist.

## 12.4. Частичный успех

Обработка вложений независима.

Ошибка одного attachment:

- не отменяет текст;
- не отменяет остальные вложения;
- добавляет отдельное предупреждение в итоговую публикацию.

## 12.5. Видео

Если VK не предоставляет доступный для скачивания видеоресурс либо скачивание не удалось:

- остальные части публикации отправляются;
- в публикации добавляется явная ошибка для конкретного видео.

---

# 13. Формирование Telegram-публикации

## 13.1. Сообщение VK-чата

Логически публикация содержит:

1. имя и фамилию автора как гиперссылку на VK;
2. исходный текст без изменения;
3. поддерживаемые вложения;
4. отдельные предупреждения по пропущенным вложениям;
5. `#извк`;
6. при `@all` — `#извкважно`.

Если Telegram-ограничения не позволяют разместить всё в одном Telegram-message, система может использовать несколько связанных сообщений, не теряя исходный текст и вложения.

## 13.2. Пост стены

Логически публикация содержит:

1. исходный текст;
2. поддерживаемые вложения;
3. предупреждения по каждому пропущенному вложению;
4. ссылку на оригинальный пост VK;
5. `#изстенывк`.

---

# 14. Ошибки и fallback

## 14.1. Недоступный target topic

Если выбранный топик Telegram отсутствует / недоступен:

1. отправить публикацию в General topic;
2. уведомить всех owners;
3. если отправка успешна — считать доставку успешной.

## 14.2. Attachment error

Не уведомлять всех owners.

Ошибка описывается внутри самой Telegram-публикации.

## 14.3. Toggle changes

После изменения toggle-настройки:

- сохранить значение в SQLite;
- уведомить всех owners (кроме самого изменяющего owner);
- отправить им актуальную клавиатуру.

---

# 15. Безопасность

Секретами являются:

- Telegram Bot Token;
- Telegram API Hash;
- Telethon session;
- VK token;
- MTProto Proxy secret, если он считается секретным в используемой инфраструктуре.

Они не должны попадать в публичный репозиторий.

Telegram-бот не должен отвечать неавторизованным Telegram User ID.

---

# 16. Нефункциональные требования

- Все настройки должны сохраняться между перезапусками.
- Изменение обычной конфигурации не должно требовать редактирования `.env`.
- Изменение обычной конфигурации не должно требовать перезапуска приложения.
- Критическая инфраструктурная ошибка на startup должна приводить к явному завершению приложения, а не к частично работающему состоянию.
- Пользовательские ошибки должны давать понятное сообщение, а не traceback / технический exception.
- Уже опубликованные сообщения и посты не синхронизируются после редактирования или удаления в VK.
