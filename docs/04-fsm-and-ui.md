# 1. Принципы интерфейса

- Пользователь не должен запоминать внутренние ID.
- Все основные действия доступны через клавиатуру.
- В FSM всегда должна быть возможность отменить действие.
- Во вложенных меню должна быть кнопка `← Назад`.
- VK-бот не использует модель Telegram slash-команд.
- Telegram-бот может использовать `/start` и служебную команду регистрации чата.
- Пагинация VK-клавиатуры не используется.
- Список топиков выводится текстом с порядковыми номерами.

---

# 2. VK-бот — главное меню

Постоянная клавиатура:

- `Алиасы`
- `Помощь`

Ручная пересылка запускается не кнопкой, а фактом получения одного пересланного сообщения.

# 3. VK-бот — Help

Одинаковую справку открывают (регистронезависемый):

- `Начать`;
- `Помощь`;
- `Помоги`;
- `Help`;
- кнопка `Помощь`.

Справка содержит:

1. как вручную переслать одно сообщение;
2. как выбрать топик по номеру;
3. как использовать алиас;
4. как создать / изменить алиас;
5. как отменить операцию;
6. что автоматически пересылаются сообщения с `@all` и/или хештегом, если соответствующие функции включены.

# 4. VK-бот — ручная пересылка

Состояние FSM хранится эфемерно per-user (ключ — `from_id`) и теряется при перезапуске; незавершённая операция не меняет бизнес-состояние.

## State: IDLE

Обычное состояние.

### Event: получено одно пересланное сообщение без текста

Переход → `WAIT_DESTINATION`.

Бот сохраняет только это сообщение как pending message.

Перед списком проверяется доступность ручного потока: если Telegram-чат не зарегистрирован или нет ни General, ни доступных топиков, бот отвечает ошибкой конфигурации, FSM не запускается и попытка доставки не создаётся.

Бот отвечает:

```text
Куда отправить сообщение?

1. General
2. Важные
3. Группа 01-24
4. Группа 02-24

Можно отправить только номер топика.
```

Клавиатура:

- `Отмена`

### Event: получено одно пересланное сообщение с текстом

Текст считается алиасом (включая цифры):

- активный алиас → публикация сразу;
- неизвестный алиас → сообщение об ошибке, список топиков и переход в `WAIT_DESTINATION`;
- устаревший алиас → ошибка недоступности, актуальный список и предложение исправить/удалить алиас; публикация не отправляется, General не подставляется.

### Event: получено два или более сообщений

FSM не запускается.

Ответ:

```text
Можно переслать только одно сообщение за одну операцию.
Отправьте одно сообщение отдельно.
```

---

## State: WAIT_DESTINATION

Допустимый ввод:

- номер топика;
- `Отмена`.

Алиасы в этом состоянии не принимаются.

### Если введён корректный номер

Переход → `SENDING`.

### Если номер не существует

Бот отвечает:

```text
Номер не найден.

Выберите топик по номеру:

1. General
2. Важные
3. Группа 01-24
4. Группа 02-24
```

FSM остаётся в `WAIT_DESTINATION`.

### Если выбранный топик стал недоступен

Выбор отклоняется с сообщением о недоступности топика; список повторяется. General вместо недоступного именованного топика не подставляется.

### Если `Отмена`

Pending message удаляется.

Переход → `IDLE`.

---

## State: SENDING

Бот пытается создать Telegram-публикацию.

### Success

Бот сообщает об успешной отправке.

Pending message очищается.

Переход → `IDLE`.

### Failure

Бот сообщает понятную ошибку.

Pending message очищается либо возвращается в `WAIT_DESTINATION` — конкретное поведение определяется типом ошибки.

Реакция 👍 исходному VK-сообщению при ручной пересылке не ставится ни при успехе, ни при ошибке.

# 5. VK-бот — FSM алиасов

## Вход

Пользователь нажимает `Алиасы`.

Бот показывает:

```text
Telegram-топики:

1. Важные — алиас: важное
2. Группа 01-24 — алиас: 1
3. Группа 02-24 — алиас: 2
4. Новости — алиас не задан
```

Клавиатура:

- `Добавить`
- `Изменить`
- `Удалить`
- `← Назад`

---

## 5.1. Добавить алиас

### State: ALIAS_ADD_WAIT_TOPIC

Бот:

```text
Введите номер топика, для которого хотите добавить алиас.
```

Клавиатура:

- `Отмена`

После корректного номера → `ALIAS_ADD_WAIT_VALUE`.

### State: ALIAS_ADD_WAIT_VALUE

Бот:

```text
Введите новый алиас.
```

Проверки:

- алиас не пустой;
- без пробелов;
- не занят другим алиасом пользователя;
- не совпадает с системными командами / кнопками;
- регистр при сравнении игнорируется.

При успехе:

```text
Алиас "важное" назначен топику "Важные".
```

Переход в главное меню алиасов.

---

## 5.2. Изменить алиас

### State: ALIAS_EDIT_WAIT_TOPIC

Бот просит номер топика.

После корректного номера показывает текущий алиас и переходит → `ALIAS_EDIT_WAIT_VALUE`.

### State: ALIAS_EDIT_WAIT_VALUE

Бот просит новый алиас.

После успешной валидации старое значение заменяется.

Возврат в меню алиасов.

---

## 5.3. Удалить алиас

### State: ALIAS_DELETE_WAIT_TOPIC

Бот просит номер топика.

Если алиас существует:

```text
Удалить алиас "важное" у топика "Важные"?
```

Кнопки:

- `Да`
- `Отмена`

После `Да` алиас удаляется.

# 6. Telegram-бот — доступ

На любое входящее событие сначала проверяется Telegram User ID.

## Authorized

ID есть в `OWNER_IDS`.

Обработка продолжается.

## Unauthorized

ID нет в `OWNER_IDS`.

Бот:

- не отвечает;
- не показывает клавиатуру;
- не сообщает причину отказа.

# 7. Telegram-бот — первичная настройка

## State: TG_UNREGISTERED

Owner отправляет `/start` в личке.

Бот отвечает текстом онбординга:

```text
Telegram-чат ещё не зарегистрирован.

1. Добавьте этого бота в нужный Telegram-чат.
2. Выдайте ему необходимые права.
3. Выполните команду /register внутри этого чата.
```

Приватный `/start` переводит owner в режим регистрации: хранится глобальное FSM-состояние по user_id. Клавиатура при этом снимается (ReplyKeyboardRemove).

---

## Регистрация внутри Telegram-чата

Команда регистрации — `/register` (допускается `@BotUsername`-форма). После получения команды:

1. команда принимается только в групповом контексте (`group`/`supergroup`) и только от owner с активным режимом регистрации;
2. при несоответствии — молчаливое игнорирование (никаких ответов посторонним);
3. повторный `/register` в уже зарегистрированном чате — молчаливое игнорирование без изменений;
4. проверить необходимые права бота;
5. при недостатке прав остановить мастер;
6. явно перечислить недостающие права (для каждого права — отдельная строка);
7. потребовать выдать права и повторить проверку; мастер остаётся активным;
8. после успеха сохранить Telegram-чат;
9. через Telethon получить список топиков;
10. сохранить актуальные топики;
11. очистить FSM и временный group-скоуп команды `/register`;
12. отправить owner в личку актуальную главную клавиатуру.

`/cancel` отменяет текущее действие, очищает FSM и возвращает ReplyKeyboardRemove (незарегистрированный чат) или главную клавиатуру (зарегистрированный чат).

# 8. Telegram-бот — главное меню owner

После регистрации чата главная клавиатура (`ReplyKeyboardMarkup`, `resize_keyboard`, `is_persistent`) содержит:

- `Включить автопересылку по @all` / `Отключить автопересылку по @all`
- `Включить автопересылку по хештегам` / `Отключить автопересылку по хештегам`
- `Включить автопересылку постов сообщества` / `Отключить автопересылку постов сообщества`
- `Настроить топик назначения автопересылки сообщений чата`
- `Настроить топик назначения автопересылки постов стены`
- `Список настроек топиков`
- `Диагностика доставки`
- `Сменить Telegram-чат`

Текст каждой toggle-кнопки зависит от текущего состояния. Inline-клавиатуры не используются.

# 9. Toggle-кнопки

Есть три независимых toggle:

1. `@all`;
2. хештеги;
3. посты стены.

## Если функция включена

Кнопка:

```text
Отключить автопересылку ...
```

## Если функция выключена

Кнопка:

```text
Включить автопересылку ...
```

После нажатия:

1. значение меняется;
2. сохраняется в SQLite;
3. owner получает подтверждение;
4. всем owners отправляется уведомление об изменении, кроме овнера который выполнил изменение. Ему просто прилетает обновленная клавиатура;
5. всем owners отправляется актуальная обновлённая клавиатура.

`/start` всегда формирует клавиатуру заново из текущего состояния БД.

# 10. Настройка топика сообщений VK-чата

Owner нажимает:

`Настроить топик назначения автопересылки сообщений чата`

Бот выводит актуальный список (General — первым; недоступные топики помечаются `(недоступна)` и не выбираются):

```text
Выберите топик:

1. General
2. Важные
3. Группа 01-24
4. Группа 02-24
```

Клавиатура:

- `Отмена`
- `← Назад`

FSM ожидает порядковый номер.

## Корректный номер

Named topic: сначала выполняется proof-send в выбранный топик, и только затем topic id сохраняется.

General: сохраняется сразу как явно настроенный General (`configured=true`, topic id отсутствует), без proof-send.

Ответ (named):

```text
Топик для автоматической пересылки сообщений VK:
Важные
```

Ответ (General):

```text
Топик для автоматической пересылки сообщений VK:
General
```

## Недоступный номер

Если выбранный топик помечен недоступным, выбор отклоняется с понятной ошибкой, список повторяется, FSM остаётся в ожидании.

## Некорректный номер

Бот сообщает об ошибке и повторяет список.

# 12. Список настроек топиков

Owner нажимает:

`Список настроек топиков`

Бот выводит только полезное состояние привязок, например:

```text

└ Сообщения VK-чата

```

Если назначение не задано:

```text
Сообщения VK-чата:

Посты стены VK:
не настроено
```

Если назначен General, отображается:

```text
General
└ Сообщения VK-чата
```

Клавиатура:

- `Обновить список`
- `← Назад`

# 13. Обновление списка топиков

Owner нажимает `Обновить список`.

Бот:

1. обращается к Telethon;
2. получает актуальный список топиков зарегистрированного Telegram-чата;
3. обновляет локальные данные (включая флаги `is_closed`/`is_hidden` и деактивацию исчезнувших топиков);
4. проверяет, существуют ли назначенные топики;
5. показывает обновлённый список.

Если назначенный топик исчез:

- настройка может оставаться сохранённой для диагностики;
- owner получает явное предупреждение, какой именно назначенный топик больше не найден;
- при реальной публикации используется General fallback.

---

# 13.1. Диагностика доставки

Owner нажимает `Диагностика доставки`.

Бот выводит компактный список терминальных записей (ambiguous и failed_permanent), например:

```text
Диагностика доставки:

1. ambiguous — vk_message 111:222:333
2. failed_permanent — vk_wall 111:-999:5
```

Если записей нет: сообщение о том, что проблемных доставок нет.

Выбор номера открывает детали записи: источник, назначение, статус, время, известные message ids, текст ошибки. Для ambiguous выводится явное предупреждение, что автоматический повтор запрещён.

Клавиатура деталей:

- `Пометить просмотренной`
- `← Назад`

`Пометить просмотренной` доступно только для ambiguous-записи; после пометки запись остаётся в истории, но больше не требует просмотра.

# 14. Смена Telegram-чата

Owner нажимает:

`Сменить Telegram-чат`

Бот:

```text
Текущий Telegram-чат будет отвязан.
Все настройки Telegram-интеграции будут сброшены до заводского состояния.

Продолжить?
```

Кнопки:

- `Да`
- `Отмена`

## `Отмена`

Ничего не меняется.

## `Да`

Удаляются:

- зарегистрированный Telegram-чат;
- выбранный топик сообщений VK-чата;
- выбранный топик стены;
- сохранённые привязки топиков.

Toggle возвращаются к default:

- `@all` — включено;
- хештеги — включены;
- посты стены — включены.

FSM возвращается в `TG_UNREGISTERED`.

---

# 15. Навигация и отмена

Правило для всех FSM:

- `← Назад` возвращает на предыдущий экран;
- `Отмена` завершает текущую изменяющую операцию;
- отменённая операция не должна частично менять БД.

VK-бот не использует пагинацию клавиатуры.

Telegram-бот также не обязан использовать пагинацию, пока список топиков остаётся разумного размера; сами топики выводятся текстовым списком с номерами.

---

# 16. Уведомления owners

## Обязательно всем owners

Уведомлять всех owners:

- после изменения любого toggle (инициатору — прямое подтверждение с клавиатурой, остальным — рассылка с обновлённой клавиатурой);
- если настроенный топик недоступен и использован General fallback;
- при терминальной проблеме доставки автоматического потока: `ambiguous` или `failed_permanent`;
- при history gap VK Long Poll (`failed=1`/`failed=3`), один раз на эпизод;
- при критической ошибке рабочей конфигурации, которую возможно сообщить уже запущенным приложением.

## Не требуется массовое уведомление

Не рассылать всем owners отдельные уведомления:

- об ошибке конкретного видео;
- о файле > 50 МБ;
- о неподдерживаемом attachment;
- об отсутствии настройки (ненастроенный destination — молчаливый no-op, а не ошибка).

Такие ошибки отображаются внутри соответствующей Telegram-публикации.

# 17. Поведение без настройки

| Ситуация | Автоматический поток | Ручная пересылка |
|---|---|---|
| Telegram-чат не зарегистрирован | молчаливый пропуск; без ответа/уведомлений/публикации/записи ledger/👍; DEBUG-причина `telegram_chat_not_registered` | понятная ошибка пользователю VK; без FSM, без попытки доставки, без General |
| Чат зарегистрирован, но соответствующее auto-назначение не настраивалось | пропускается только эта функция; вторая оценивается независимо; DEBUG-причина `destination_not_configured` | не влияет: ручной поток предлагает General и доступные топики |
| Ручной список назначений недоступен | auto-потоки оцениваются по своим настройкам | понятная ошибка пользователю VK; без сломанного FSM и попыток доставки |
| Auto-назначение явно настроено, но топик исчез/закрыт/скрыт | General fallback + уведомление owners; успешная доставка и 👍 | не влияет, если пользователь не выбрал этот же недоступный топик |
| Пользователь явно выбрал недоступный именованный топик вручную | — | понятная ошибка и актуальные альтернативы; General не подставляется |
