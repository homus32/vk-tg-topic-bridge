# 1. Назначение

Система связывает один чат сообщества VK и стену этого сообщества с одним Telegram-чатом, в котором используются топики.

Основные задачи:

- автоматически переносить важные сообщения из VK-чата в Telegram;
- автоматически переносить посты стены сообщества VK в отдельный Telegram-топик;
- позволять пользователю вручную пересылать одно сообщение через VK-бота в выбранный Telegram-топик;
- управлять настройками интеграции через Telegram-бота;
- позволять пользователям VK назначать удобные алиасы Telegram-топикам.

---

# 2. Границы проекта

Проект рассчитан на:

- одно сообщество VK;
- один чат сообщества VK;
- один Telegram-чат;
- множество топиков внутри Telegram-чата;
- небольшой фиксированный список владельцев системы.

Проект не является multi-tenant системой и не предназначен для одновременного обслуживания множества независимых VK-сообществ и Telegram-чатов.

---

# 3. Терминология

**Telegram-чат** — зарегистрированный чат, в котором используются топики.

**Топик** — отдельное направление внутри Telegram-чата.

**Owner / владелец** — Telegram-пользователь, чей Telegram User ID указан в `OWNER_IDS` в `.env`.

**Автопересылка VK-чата** — автоматическая публикация сообщения VK, если оно содержит `@all` и/или любой хештег.

**Автопересылка стены** — автоматическая публикация нового поста стены сообщества VK.

**Алиас** — короткое пользовательское имя Telegram-топика, например `важное`, `1`, `2`.

---

# 4. Роли

## 4.1. Owner

Может:

- зарегистрировать Telegram-чат;
- менять Telegram-чат;
- включать и отключать автопересылку по `@all`;
- включать и отключать автопересылку по хештегам;
- включать и отключать автопересылку постов стены;
- выбирать один топик для автопересылки сообщений VK-чата;
- выбирать отдельный топик для постов стены VK;
- просматривать настройки топиков;
- обновлять список топиков;
- получать критические уведомления о проблемах.

Telegram-бот не отвечает пользователям, которых нет в `OWNER_IDS`.

## 4.2. Пользователь VK-бота

Может:

- вручную пересылать одно сообщение в Telegram;
- выбирать топик по номеру из предложенного списка;
- использовать настроенный алиас;
- добавлять, изменять и удалять собственные алиасы;
- получать Help.

---

# 5. Состав системы

Система состоит из:

- VK-бота / интеграции с VK API;
- Telegram-бота;
- пользовательского Telegram MTProto-клиента;
- SQLite-базы данных;
- отдельного скрипта первичной авторизации Telegram-пользователя.

Telegram-бот отвечает за публикации и административный интерфейс.

Пользовательский Telegram MTProto-клиент используется для чтения структуры Telegram-чата и получения актуального списка топиков.

# 6. Автоматическая пересылка сообщений VK-чата

## 6.1. Условие пересылки

Сообщение автоматически публикуется в Telegram, если включено соответствующее правило и сообщение содержит:

- `@all`;
- любой хештег вида `#текст`;
- одновременно `@all` и любой хештег.

Для всех автоматически пересылаемых сообщений VK-чата используется **один общий настроенный Telegram-топик**.

`@all` и хештеги не определяют разные направления маршрутизации.

## 6.2. Исходный текст

Оригинальный текст VK-сообщения сохраняется полностью и не переписывается.

Сохраняются:

- исходные хештеги;
- `@all`;
- исходный порядок текста.

Если входящее событие VK содержит урезанную версию сообщения (`is_cropped = true`), сервис обязан дополнительно запросить полную версию сообщения до анализа и публикации.

## 6.3. Автор

В Telegram указывается имя и фамилия автора исходного сообщения.

Имя автора является гиперссылкой на профиль пользователя VK.

## 6.4. Служебные хештеги

Бот добавляет свои служебные хештеги, не меняя исходный текст:

- для любого автоматически пересланного сообщения VK-чата — `#извк`;
- если исходное сообщение содержит `@all` — дополнительно `#извкважно`.

| Исходное сообщение | Добавляемые теги |
|---|---|
| содержит только `#хештег` | `#извк` |
| содержит только `@all` | `#извк #извкважно` |
| содержит `@all` и `#хештег` | `#извк #извкважно` |

Если одновременно присутствуют `@all` и хештег, создаётся одна Telegram-публикация.

## 6.5. Реакция VK

После успешного создания Telegram-публикации VK-бот ставит оригинальному сообщению реакцию 👍.

Реакция означает, что сообщение обработано системой и соответствующая публикация в Telegram создана.

Если часть вложений была пропущена или заменена текстовым предупреждением, но Telegram-публикация была успешно создана, реакция всё равно ставится.

Если Telegram-публикация не была создана вообще, реакция не ставится.

---

# 7. Пересылка постов стены VK

Новый пост стены сообщества автоматически публикуется в отдельный настроенный Telegram-топик, если автопересылка стены включена.

В Telegram передаются:

- полный текст поста;
- поддерживаемые фото;
- поддерживаемые видео;
- поддерживаемые документы;
- ссылка на оригинальный пост VK;
- служебный хештег `#изстенывк`.

Ссылка на оригинальный пост обязательна.

Посты стены и сообщения VK-чата используют разные настраиваемые топики назначения.

---

# 8. Поддерживаемый контент

## 8.1. Поддерживается

- текст;
- фото;
- видео;
- документы / файлы размером до 50 МБ.

Собственный продуктовый лимит файла — **50 МБ**, даже если инфраструктура Telegram технически позволяет больше.

## 8.2. Не поддерживается

- голосовые сообщения;
- аудиозаписи;
- видеосообщения / «кругляшки»;
- другие типы вложений VK, которые явно не входят в поддерживаемый список.

## 8.3. Ошибка отдельного вложения

Ошибка одного вложения не должна отменять всю публикацию.

Если конкретное вложение невозможно перенести, в Telegram-публикации явно указывается причина по каждому такому вложению.

Примеры:

- `⚠️ Видео не удалось скачать из VK.`
- `⚠️ Файл "example.zip" не перенесён: размер превышает 50 МБ.`
- `⚠️ Вложение типа "аудиозапись" не поддерживается.`
- `⚠️ Вложение типа "голосовое сообщение" не поддерживается.`

Ошибки неподдерживаемых или недоступных вложений не отправляются отдельным уведомлением всем owners.

# 9. Ручная пересылка через VK-бота

Ручная операция работает только с **одним пересланным сообщением за раз**.

После получения одного пересланного сообщения VK-бот:

1. сохраняет его как ожидающее отправки;
2. показывает список доступных Telegram-топиков с порядковыми номерами;
3. ожидает номер топика;
4. позволяет отменить операцию;
5. после выбора публикует сообщение в выбранный Telegram-топик.

Если вместе с пересланным сообщением передано текстовое сообщение, этот текст считается алиасом топика (включая цифры). Активный алиас отправляет сразу; неизвестный алиас показывает ошибку и список топиков для выбора номера; устаревший алиас (топик исчез/закрыт/скрыт) показывает ошибку недоступности, текущий список топиков и предложение исправить или удалить алиас — без автоматического перехода в General.

Выбор номера в режиме ожидания принимает только номер или отмену; алиасы там не принимаются.

Если пользователь передал два или более сообщений одной операцией, бот:

- сообщает об ошибке;
- ничего не публикует;
- не запускает FSM выбора направления.

Если исходное сообщение является ответом на другое сообщение, связь reply не переносится.

Если исходное сообщение содержит вложенные пересланные сообщения (`fwd_messages`), они не разворачиваются как отдельная цепочка. Система работает только с основным выбранным сообщением.

Ручная публикация содержит ссылку на исходного автора VK и отдельную ссылку на инициирующего пользователя VK. Реакция 👍 за ручную публикацию не ставится. Если явно выбранный именованный топик стал недоступен, ручная публикация завершается понятной ошибкой и не подменяется General.

# 10. Алиасы топиков

Пользователь VK-бота может назначать собственные алиасы Telegram-топикам.

Примеры:

- `важное` → `Важные`;
- `1` → `Все для группы 01-24 ИСиП ОД 11`;
- `2` → `Все для группы 02-24 ИСиП ОД 11`.

Алиасы:

- уникальны в пределах пользователя;
- сравниваются без учёта регистра;
- не содержат пробелов;
- не могут совпадать с системными командами / кнопками;
- могут быть добавлены, изменены и удалены.

Если пользователь ввёл неизвестный алиас, VK-бот:

1. сообщает, что алиас не найден;
2. предлагает настроить алиасы;
3. выводит список топиков с номерами;
4. переводит пользователя в обычный интерактивный выбор топика.

# 11. VK Help

В VK нет модели Telegram slash-команд, поэтому следующие значения являются обычными текстовыми триггерами и/или кнопками клавиатуры:

- `Начать`;
- `Помощь`;
- `Помоги`;
- `Help`.

Команды регистро-независимые. 

Все они открывают одну и ту же справку.

Help объясняет:

- как вручную переслать сообщение;
- как выбрать топик;
- что такое алиасы;
- как настроить алиас;
- как работает автоматическая пересылка по `@all`;
- как работает автоматическая пересылка по хештегам.

---

# 12. Telegram-бот как административный интерфейс

Доступ разрешён только owners из `.env`.

После регистрации Telegram-чата владелец получает постоянную клавиатуру.

Основные действия:

- включить / отключить автопересылку по `@all`;
- включить / отключить автопересылку по хештегам;
- включить / отключить автопересылку стены;
- выбрать топик для сообщений VK-чата (включая General);
- выбрать топик для постов стены (включая General);
- посмотреть список настроек топиков;
- обновить список топиков;
- посмотреть диагностику доставки;
- сменить Telegram-чат.

Все toggle-кнопки показывают действие относительно текущего состояния.

`/start` в Telegram всегда отправляет актуальную клавиатуру на основе текущих настроек.

Регистрация чата выполняется мастером регистрации: приватный `/start` у owner открывает режим регистрации, а `/register` в целевом чате завершает регистрацию. Команды `/start`, `/cancel` и подсказки являются UX-элементами и не заменяют проверку owner на бэкенде.

После изменения toggle-настройки всем owners отправляется уведомление об изменении и обновлённая клавиатура (инициатору — прямое подтверждение, остальным — рассылка).

Для остальных типов изменений обязательная рассылка всем owners не требуется.

# 13. Смена Telegram-чата

Owner может отвязать текущий Telegram-чат и зарегистрировать новый.

Перед отвязкой требуется подтверждение.

После подтверждения все рабочие настройки Telegram-интеграции сбрасываются до заводского состояния, как будто настройка ранее не выполнялась.

Заводское состояние:

- автопересылка по `@all` — включена;
- автопересылка по хештегам — включена;
- автопересылка стены — включена;
- Telegram-чат — не зарегистрирован;
- топик сообщений VK-чата — не выбран;
- топик стены VK — не выбран;
- сохранённые привязки топиков очищены.

# 14. Ошибки и fallback

## 14.1. Недоступный Telegram-топик

Если настроенный топик автоматической пересылки удалён или недоступен:

1. публикация отправляется в General / общий топик Telegram-чата;
2. все owners получают уведомление об ошибке и использовании fallback;
3. если публикация успешно создана в General, исходному VK-сообщению ставится 👍.

Fallback применяется только к автоматическим потокам (сообщения VK-чата и посты стены) и только если destination был явно настроен. Если destination никогда не настраивался, автоматическая пересылка молча пропускает событие без публикации и без уведомлений. Ручная пересылка никогда не подменяет недоступный выбранный именованный топик на General: пользователь получает понятную ошибку и актуальный список топиков.

## 14.2. Недостающие Telegram-права

При регистрации Telegram-чата бот обязан проверить необходимые права.

Если прав недостаточно, бот должен явно сообщить owner:

- какие права отсутствуют;
- что нужно выдать эти права;
- что настройка не может считаться завершённой до исправления.

## 14.3. Недоступное вложение

Публикация продолжается.

В самой Telegram-публикации добавляется отдельное предупреждение для каждого пропущенного вложения.

---

# 15. Что система намеренно не делает

Система не синхронизирует изменения после первоначальной публикации.

Не отслеживаются:

- редактирование VK-сообщения;
- удаление VK-сообщения;
- редактирование поста стены;
- удаление поста стены.

Telegram-публикация остаётся в том состоянии, в котором была создана на момент обработки исходного события.

Также система:

- не переносит reply-контекст;
- не разворачивает `fwd_messages` как отдельную цепочку;
- не пытается поддерживать все возможные типы вложений VK;
- не обрабатывает несколько вручную пересланных сообщений одной операцией.
