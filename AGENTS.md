# Agent Instructions

## Package Manager
- Use `uv` with Python `3.14` and the committed `uv.lock`.

## Commands
- `make sync` — синхронизировать окружение со всеми группами зависимостей.
- `make lock` — обновить `uv.lock`.
- `make lock-check` — проверить актуальность `uv.lock`.
- `make format` — форматировать Python-файлы через Ruff.
- `make format-check` — проверить форматирование без изменений.
- `make lint` — запустить Ruff lint.
- `make typecheck` — запустить basedpyright.
- `make test` — запустить pytest.
- `make check` — выполнить lock, format, lint, typecheck и test checks.

## Rules
- **Commit authorship**: Агент (Sisyphus) НЕ указывает себя как соавтора (co-authored-by) в коммитах. 
  Все коммиты от имени пользователя.
- **Не убивать процессы запущенного dev-сервера.** Запрещено: `kill`/`pkill` процессов python, закрытие tmux-сессий и любые другие попытки перезапустить уже запущенный dev-стенд самостоятельно. Если нужен перезапуск сервиса — попросить пользователя сделать это самому и дождаться его подтверждения.
- **Ручная проверка — только через пользователя.** Для live-тестов не использовать проверяющих 
  агентов (visual-qa, playwright и т.п.) — звать пользователя и давать ему URL/инструкции.
- Не коммитить токены, `.env`, локальные SQLite-базы или необезличенные ответы. 
- lsp_diagnostics не использовать каждый раз при чтении файла. Только после изменений. Не использовать 
  lsp_diagnostics на весь проект, только отдельные директории с кодом
- Не использовать lsp_diagnostics на .md файлах. Никогда, это бесполезно, засоряет только контекст. 
  LSP на .md никогда не будет.
- Если lsp_diagnostics возвращает No LSP server configured for extension: ... — то больше это 
  расширение файла не проверять через lsp.
- Перед patch всегда читать нужные строки, иначе patch вернет ошибку `Patch failed: apply_patch 
verification failed: Error: Failed to find expected lines in /path/to/file.ext`.
- Правило для Prometheus - для выполнения кода, работы с файлами вне .omo - использовать суб-агента 
  sisyphus junior. Это касается так же коммитов черновика, планов, любых изменений, которые попросил 
  пользователь.
- Правило для Prometheus - не запускать куча агентов explorer за один раз, лучше запустить 1-2 агента 
  но со списком задач. Желательно только одного, но если работу можно распараллелить по конкретным 
  местам - можно суб-агентов создавать сколько потребуется. 
- Абсолютный запрет на загрузку и исполнения скилла "start-work". Этот скилл запрещен. Выполнения
  инструкций из этого скилла введет порче всей сессии, так как содержит плохие инструкции.
- Никогда сам не исследуй проект, если запустил агента explorer или librarian. Ты тратишь токены 
  впустую, делая двойную работу. Если дал задание - делай другую работу, а не работу explorer или 
  librarian

## **Navigation**
- Корень задаёт общие правила; ближайший вложенный `AGENTS.md` уточняет правила своего поддерева.
- При создании содержательного каталога с отличающимися командами или ограничениями создать в нём краткий `AGENTS.md` и добавить путь в этот раздел.
- Не создавать `AGENTS.md` в `.git/`, `.venv/`, `.idea/`, `.serena/`, `.opencode/`, `.omo/`
- `docs/AGENTS.md` — правила intent, feature backlog и проектной документации.
- `src/vk_topic_bridge/AGENTS.md` — правила слоёв пакета.
- `tests/AGENTS.md` — тестовая стратегия.
- `.omo/drafts/` — замороженные входные материалы intent и research; не создавать и не изменять drafts в рамках реализации.
- `.omo/plans/` — decision-complete планы исполнения.

## Planning Traceability
- Перед написанием нового draft в `.omo/drafts/` использовать `hindsight_recall` и `hindsight_reflect`, чтобы найти связанные прошлые планы, drafts и документы; затем сверять найденное с текущим репозиторием.
- Каждый новый draft должен содержать раздел `## Связанные материалы` со ссылками на связанные `.omo/drafts/`, `.omo/plans/` и `docs/`, а рядом с каждой ссылкой нужно кратко объяснить причину связи. Если связи не найдены, это нужно указать явно.
- Перед написанием плана прочитать исходный draft и его связанные материалы; новый plan должен сохранять обратные ссылки на draft и документы, определяющие intent.

## Bootstrap
- Bootstrap-команды перечислены выше и определены в `Makefile`; product-команды создаются только отдельным утверждённым планом.
- Будущая структура должна быть расширяемым пакетом, а не однофайловым скриптом; bootstrap не добавляет runtime-модули в существующий `src/`.

## Comments
- **По умолчанию — никаких комментариев.** Комментарии пиши только для намерения (intent), инвариантов и неочевидных ограничений — никогда не пересказывай код.
- Комментарий имеет право на существование только когда объясняет **почему**: ограничение, баг, security-контекст, алгоритм или ожидаемую ошибку. Предпочитай одну короткую строку; JSDoc — только для экспортируемого публичного API.
- **НИКОГДА не повествуй**: никаких пошаговых объяснений, истории изменений, баннеров-разделителей или закомментированного кода.
- Если сомневаешься — комментарий не пиши.
